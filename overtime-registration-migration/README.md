# نظام تسجيل السهر — نسخة جاهزة لقاعدة بيانات Cloudflare D1

هذه نسخة ترحيل مستقلة عن AppDeploy. لا تستخدم قاعدة بيانات AppDeploy ولا تحتوي على بيانات موظفين/سهر فعلية؛ قاعدة D1 تبدأ فارغة لتستقبل قاعدة الموظفين المعتمدة لاحقًا.

## الوظائف
- تسجيل سهرة مع التحقق من الموظف ومنع التكرار (رقم الموظف + التاريخ + وقت البداية + وقت النهاية).
- سجل الموظف وتقارير السهر حسب القسم والفترة.
- إدارة الموظفين، استيراد CSV، وتصدير التقارير من الواجهة.
- الاحتفاظ ببيانات الموظف داخل سجل السهر حتى بعد إخفائه من قائمة الموظفين.

## إعداد Cloudflare (مرة واحدة)
1. أنشئ قاعدة D1 باسم `overtime-registration-db` في لوحة Cloudflare.
2. حدّث `database_id` في `wrangler.toml` بالمعرّف الحقيقي من لوحة Cloudflare.
3. شغّل `npm install` ثم `npm run build`.
4. طبّق المخطط: `npx wrangler d1 migrations apply overtime-registration-db --remote`.
5. اربط GitHub repo مع Cloudflare Pages، واستخدم أمر البناء `npm run build` ومجلد الإخراج `dist`.
6. تأكد من وجود ربط D1 باسم `DB` في إعدادات Pages Functions. إن لم يقرأ Pages إعداد `wrangler.toml` تلقائيًا، أضف الربط من Settings > Functions > D1 database bindings.

## قاعدة الموظفين
بعد النشر، افتح «قاعدة الموظفين» واستورد ملف CSV المعتمد بالأعمدة: `code,name,department,job,shift` أو استخدم نموذج CSV الموجود في الواجهة. لا تستورد قائمة الاختبار كبيانات رسمية.

## أمان وتشغيل
- لا تضع كلمات مرور أو مفاتيح سرية في ملفات المشروع.
- احتفظ بمشروع AppDeploy القديم حتى يتم اختبار النسخة الجديدة.
- هذه الملفات لا تعني أن الاستضافة قد نُشرت بعد؛ يلزم إنشاء وربط قاعدة D1 ونشر Pages.
